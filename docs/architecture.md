# Архитектура

## Компоненты

```text
┌──────────────┐   message_new    ┌──────────────────────────────────────┐
│  VK Bots     │ ───────────────▶ │ bot.py                               │
│  Long Poll   │                  │  • дедупликация событий              │
└──────────────┘                  │  • очередь ThreadPoolExecutor        │
        ▲                         │  • блокировка на peer_id             │
        │ messages.send           │  • команды и история диалога         │
        │                         └───────────────┬──────────────────────┘
        │                                         │ messages[]
        │                                         ▼
        │                         ┌──────────────────────────────────────┐
        │                         │ prompts.py                           │
        │                         │  persona «Алина» + knowledge_base.md │
        │                         └───────────────┬──────────────────────┘
        │                                         │ system + history
        │                                         ▼
        │                         ┌──────────────────────────────────────┐
        │                         │ gigachat.py                          │
        │                         │  • OAuth, кэш access token           │
        │                         │  • retry 401 / 429 / 5xx             │
        └─────────────────────────│  • разбор choices[0].message         │
                                  └───────────────┬──────────────────────┘
                                                  │ HTTPS
                                                  ▼
                                     api.giga.chat/v1/chat/completions
```

## Поток обработки сообщения

1. Long Poll возвращает событие `message_new`.
2. Бот проверяет `event_id`: повторно доставленные события пропускаются
   (кольцевой буфер на 2000 записей).
3. Событие уходит в `ThreadPoolExecutor`; число потоков задаёт `BOT_WORKERS`.
4. Для `peer_id` берётся отдельная блокировка: один диалог обрабатывается
   последовательно, разные диалоги — параллельно.
5. Текст проверяется на команды (`/start`, `/reset`, `/help`, приветствие).
6. Обычный вопрос добавляется в историю диалога и вместе с системным промптом
   отправляется в GigaChat.
7. Ответ очищается от Markdown, режется на части до 4000 символов и отправляется
   через `messages.send(peer_id=...)`.
8. Ответ модели дописывается в историю; история обрезается до
   `MAX_HISTORY_MESSAGES`.

## Модули

| Модуль | Ответственность |
|---|---|
| `bot.py` | Long Poll, маршрутизация событий, команды, история, отправка в VK |
| `config.py` | чтение `.env`, валидация значений, типобезопасный `Config` |
| `gigachat.py` | OAuth, кэширование и обновление токена, HTTP-повторы, разбор ответа |
| `prompts.py` | тексты бота и системный промпт персоны |
| `text_utils.py` | очистка Markdown, разбиение длинных сообщений |
| `__main__.py` | точка входа `python -m vk_gigachat_bot` |

Зависимости направлены в одну сторону: `bot → prompts / text_utils / gigachat → config`.
Конфигурация не знает о VK и GigaChat, клиент GigaChat не знает о VK —
поэтому `config` и `text_utils` тестируются без сети и без реальных ключей.

## Ключевые решения

### Long Poll вместо Callback API

Long Poll не требует публичного HTTPS-адреса, домена и валидации подписи
запросов. Плата — постоянно работающий процесс. Для учебного проекта и
небольшого сообщества это выгоднее.

### `peer_id` вместо `user_id`

Ответ отправляется в тот же диалог, откуда пришло сообщение. Поэтому бот
работает и в личных сообщениях, и в беседах (`peer_id ≥ 2000000000`) без
отдельной ветки кода.

### История в памяти

Словарь `peer_id → [messages]` под замком. Просто, быстро, без внешних
зависимостей. Ограничение: история теряется при перезапуске и не
масштабируется на несколько экземпляров. Для production — Redis или PostgreSQL.

### Блокировка на диалог

Глобальный замок сериализовал бы всех пользователей. Замок на `peer_id`
сохраняет порядок сообщений внутри диалога и позволяет обслуживать разные
диалоги параллельно.

### Дедупликация событий

При переподключении Long Poll VK может повторно отдать событие. Бот хранит
последние 2000 `event_id` и пропускает повторы — иначе пользователь получил бы
два одинаковых ответа.

### Обновление токена

Access token GigaChat живёт 30 минут. Клиент обновляет его за 60 секунд до
истечения, а при `401` принудительно получает новый и повторяет запрос один раз.
Обновление защищено `threading.Lock`, чтобы параллельные диалоги не устраивали
шторм OAuth-запросов.

### Обработка ошибок API

| Ответ | Поведение |
|---|---|
| `401` | обновить access token, повторить один раз |
| `422` | один раз сократить историю до последнего сообщения и повторить |
| `429` | подождать `Retry-After` (1–60 с), до 2 повторов |
| `5xx` | пауза 3 с, до 2 повторов |
| сетевая ошибка | пауза 3 с, до 2 повторов |
| иное | пользователю — вежливая заглушка, в лог — детали |

Ошибка в одном диалоге не останавливает бота: каждое событие обрабатывается
в `_handle_event_safe` с перехватом исключений.

### Текст под VK

VK не понимает Markdown и ограничивает сообщение 4096 символами. `clean_reply`
снимает `**`, `__` и обратные кавычки, `split_vk_message` режет текст по
абзацу, затем по строке, затем по пробелу — так части остаются читаемыми.

### Конфигурация

`Config.from_env()` проверяет обязательные поля, диапазоны чисел и допустимые
значения (`scope`, `LOG_LEVEL`), нормализует `VK_GROUP_ID` (убирает минус и
префикс `club`/`public`). Ошибка конфигурации выводится один раз и завершает
процесс с кодом 1 — без «полурабочего» состояния.

### Логирование

Консоль + `logs/bot.log` с ротацией (5 МБ, 3 архива). Формат содержит время,
уровень, модуль и сообщение. Секреты не логируются.

## Ограничения архитектуры

- Один процесс — один экземпляр бота; горизонтальное масштабирование
  потребует общей истории и распределённой блокировки.
- Текстовый канал: вложения игнорируются.
- Нет метрик и health-check; состояние видно только по логам.
