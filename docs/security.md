# Безопасность

## Секреты

- `.env` исключён в `.gitignore`; в репозиторий попадает только `.env.example`
  с пустыми значениями.
- Не публикуйте `.env`, скриншоты с ключами и логи с заголовком `Authorization`.
- Ограничьте права на файл:

```bash
chmod 600 .env
```

- Запускайте бота от отдельного пользователя ОС, а не от `root`.
- Не передавайте ключи аргументами командной строки: они видны в списке процессов.

## В коде

- `Config` помечает поля с секретами `repr=False`, поэтому случайный
  `print(config)` не выведет ключи.
- Клиент GigaChat не логирует access token — только время его действия.
- Ответы API обрезаются перед записью в лог.

## Проверка перед коммитом

```bash
git check-ignore -v .env
git grep -nE "github_pat_|Bearer [A-Za-z0-9]|vk1\.a\." -- . ':!*.lock'
```

Если что-то нашлось — не коммитьте, замените на заглушку.

## При утечке

| Сервис | Действие |
|---|---|
| GigaChat | сгенерировать новый Authorization Key в Studio |
| ВКонтакте | удалить старый ключ доступа и создать новый |
| Git-история | удалить коммит, сменить ключи; считать старые скомпрометированными |

После смены ключей обновите `.env` и перезапустите процесс.
