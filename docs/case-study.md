# Кейс для портфолио

## Контекст

Учебное задание курса «Зерокодер»: сделать чат-бота для сообщества ВКонтакте,
который консультирует по курсам университета. Задание предполагало работу
с внешним LLM API и реальным мессенджером, а не консольную демонстрацию.

## Роль

Проект сделан самостоятельно: от постановки задачи и структуры проекта
до интеграций, обработки ошибок, документации и запуска.

## Задача

- принимать сообщения сообщества и отвечать в том же диалоге;
- отвечать по базе знаний о курсах, не выдумывая цены и сроки;
- держать контекст беседы и не тратить лишние токены;
- работать на обычном VPS без входящих портов;
- не терять устойчивость при ошибках внешних API.

## Ограничения

- только текст: вложения не передаются в модель;
- Long Poll требует постоянно работающего процесса;
- бесплатный тариф GigaChat ограничивает частоту и объём запросов;
- ключи должны храниться вне кода и не попадать в репозиторий.

## Решение

```text
VK Long Poll → бот → системный промпт + база знаний → GigaChat → ответ в VK
```

Что сделано:

1. **Пакет `src/vk_gigachat_bot`** с разделением ответственности:
   транспорт VK, конфигурация, клиент GigaChat, промпты, обработка текста.
2. **Интеграция с GigaChat API**: OAuth по Authorization Key, кэш access token,
   обновление за 60 секунд до истечения, повтор при `401`.
3. **Надёжность**: повторы при `429` и `5xx`, сокращение контекста при `422`,
   переподключение Long Poll, защита от повторных событий.
4. **Персона и база знаний**: промпт «Алина» с правилами и файл
   `data/knowledge_base.md`, который можно править без изменения кода.
5. **UX в VK**: статус «печатает», команды `/start`, `/reset`, `/help`,
   очистка Markdown, деление длинных ответов на части.
6. **Инженерная обвязка**: валидация `.env`, логирование с ротацией,
   тесты `pytest`, линтер `ruff`, CI на трёх версиях Python.
7. **Документация**: архитектура, настройка GigaChat и VK, деплой,
   диагностика, безопасность.

## Результат

- Бот запускается одной командой и отвечает в личных сообщениях и беседах.
- Конфигурация проверяется до старта: неверный ключ или scope видны сразу.
- Временные сбои API не требуют ручного вмешательства.
- Изменение базы знаний не требует правки кода.
- Репозиторий готов к публикации: чистая история, ветки, тесты, CI, лицензия.

## Чему научилась

- проектировать небольшой сервис слоями и удерживать зависимости в одну сторону;
- работать с OAuth и токенами внешнего API, включая их жизненный цикл;
- обрабатывать ошибки внешних сервисов по коду ответа, а не «на глаз»;
- продумывать конкурентность: пул потоков, блокировки, идемпотентность событий;
- писать документацию, по которой проект можно поднять с нуля;
- держать секреты вне репозитория и проверять это перед коммитом.
